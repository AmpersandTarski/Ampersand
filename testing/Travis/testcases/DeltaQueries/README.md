# Regression test for the size of a candidate query

This test exists because a script that compiled with v5.9.7 stopped the compiler from v5.9.8 to v5.11.0
with the fatal "The SQL that is being generated by your script, is probably way too complex" (issue #1728).

For every conjunct the compiler writes one candidate query per relation into `conjuncts.json` (issue #1684).
A runtime that maintains violations incrementally uses that query
to find the pairs whose violation status a transaction may have changed.
The compiler used to write the candidate set as a list with one term per occurrence of the relation,
and every term held the whole violation term,
so the query grew with the square of the number of occurrences.
It now writes one nested term and computes every repeated subterm once, in a `WITH` clause,
so the query grows with the size of the violation term (claims PRF-16 to PRF-18).

`LongCandidateQuery.adl` is the script of the issue.
The relation `same` occurs eleven times in the term of its `ENFORCE` statement.
The violation query of that term is about 36,000 characters long,
and the candidate query for `same` about 60,000; it used to be more than 1,000,000.

The test runs `ampersand proto --no-frontend` and expects exit code 0.
